## 2. Вынос настроек из кода (Critical)

```csharp
builder.Services.AddOptions<JwtSettings>().Validate(o =>
    Encoding.UTF8.GetByteCount(o.SecretKey) >= 32 && o.ExpiryMinutes > 0, "JwtSettings invalid");
```

## 3. Health-checks (High)

Нет `/health`, `AddHealthChecks`, `MapHealthChecks`; в контрактах их тоже нет
(`../api-contracts.md` — grep `health` → 0). Без readiness compose не может ждать миграций/БД,
и без liveness `HEALTHCHECK` в Docker не работает.

```csharp
builder.Services.AddHealthChecks()
    .AddCheck("self", () => HealthCheckResult.Healthy())        // liveness
    .AddMySql(connectionString, name: "mysql",
        failureStatus: HealthStatus.Degraded);                   // readiness
app.MapHealthChecks("/health/live", new HealthCheckOptions {
    Predicate = r => r.Name == "self" });
app.MapHealthChecks("/health/ready", new HealthCheckOptions { Predicate = _ => true });
```

Пакет `AspNetCore.HealthChecks.MySql` (Pomelo-совместимый) + `Microsoft.Extensions.HealthChecks` из SDK.

## 4. Часовой пояс для BR3/BR33 (High)

Весь код считает время в UTC: `src/WorkTime.Api/Middleware.cs:234`, `:270`, `:287`, `:296`,
`Controllers/WorkDaysController.cs:95`, `Controllers/AdminController.cs:84`,
`Controllers/ReportsController.cs:143`, `TokenService.cs:30`. Схема БД хранит `DATETIME` без
информации о TZ (`../project/database/schema.sql:7,25,59,92`) и не задаёт `CHARSET/COLLATE/ENGINE`.
БП3 — автозавершение в 23:59:59 (`../docs/business_rules.md:20`), БП33 — бэкап в 03:00 и 30 дней
хранения (`../docs/business_rules.md:64`). Ни одной настройки TZ нет → фоновый `IHostedService`
в контейнере с `TZ=UTC` сработает на 3 часа позже московского времени, а `mysqladmin`/`mysqldumpd`
sidecar вообще зависит от TZ контейнера.

```csharp
builder.Services.Configure<TimeSettings>(builder.GetSection("TimeSettings")); // TimeZoneId=Europe/Moscow
var tz = TimeZoneInfo.FindSystemTimeZoneById(settings.TimeZoneId);
var localNow = TimeZoneInfo.ConvertTimeFromUtc(DateTime.UtcNow, tz);
```
