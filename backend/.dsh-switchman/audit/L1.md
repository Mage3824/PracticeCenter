## 8. Что признано корректным

- Стрелки зависимостей csproj и отсутствие обратных ссылками; Domain без зависимостей.
- `IRepositories.cs:2` — все методы async + явный `CancellationToken` во всех 9 интерфейсах.
- Application не знает ни ASP.NET, ни EF: единственный «внешний» пакет — Argon2 (`WorkTime.Application.csproj:9`); Infrastructure не реализует доменные правила (только выборки/фильтры, `DevRepositories.*`), правила остаются в `WorkTimeRules.cs` и сервисах.
- `Wire.cs:232-233` — конвертеры не знают репозиториев и правил, только rename/format; `WireFormats.cs:151-230` — единый центр скалярных форматтов контракта (дата, timestamp, HH:mm, минуты, Guid).
- DTO-классы Application не импортируют Domain (`Dto/*.cs` чисты) — изоляция есть, проблема только в том, что они не используются.
- Порядок middleware явный и корректный; exception-handler оборачивает весь pipeline (`Program.cs:180`), ProblemDetails + envelope централизованы в `Middleware.cs:24-135` и `ErrorEnvelope.cs:136-151`; model-state factory тоже отдаёт контрактный envelope (`Program.cs:98-138`).
- Named policies (`AuthorizationPolicies.cs`) и Swagger security-filter (`Program.cs:162`) — требование Bearer только на защищённых endpoint'ах.
- Гейты Users/WorkTime/Absences применяются последовательно в сервисах; `BreakService` использует тот же гейт WorkTime, что и `WorkTimeService` (`BreakService.cs:128`, `WorkTimeService.cs:115,154,194`) — одна aggregate-lock на рабочий день с брейками.
- `RequestContextProvider.cs:6-33` — тонкий scoped-обёртка над `IHttpContextAccessor`, без логики; `DevSeed.cs` ограничен Development + ручным запуском (`Program.cs:171`), интеграционные тесты сеются сами.
